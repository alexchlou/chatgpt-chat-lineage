# Daily task template

This is a template, not an installed schedule. Ask the user to select the profile, private dataset, timezone, time, and bounded scope. Enable metadata/Obsidian/email only within their explicit authorization. Update an existing task rather than creating duplicates.

Use the following prompt after replacing its uppercase placeholders in the local scheduler:

> Use $chatgpt-conversation-rename. Read RECOVERY.md, RESEARCH_DATA.md, KNOWLEDGE_GRAPH.md, and the local research_config.json. In CONFIGURED_TIMEZONE, derive one logical run ID from this scheduled date and time. Resume it before selection; only Unknown run_id permits freezing the current first AUTHORIZED_COUNT recent ChatGPT conversations, excluding pinned items. Never replace or refill frozen URLs. Confirm the authorized Chrome profile and unique signed-in account through supported visible CUA. Default to English; preserve accurate titles and read enough actual context. Use durable mode with the committed start, PLANNED, arm, and single commit gates. Reset invalidates all handles and creates a new session epoch. Unknown saves allow verification only and block next-target navigation. Convert fresh atomic results with toEvent; cached outcomes are skipped. Retry exact serialized metadata without changing time or evidence. Record all outcomes and finish COMPLETE/PARTIAL/INTERRUPTED using the original denominator. Export the same consistent snapshot to CSV, JSONL, graph, and the explicitly configured Obsidian vault. Check hashes, update ID, evidence tiers, and quarantine; repeated exports must add nothing. Register E1/H only with specific two-ended terminal sources and sufficient metadata, never to fill the graph. Do not promote evidence on recovery or repetition. For restored loading failures, follow the same-run correction branch and retain the old block. If self-addressed email is explicitly enabled, follow EMAIL_ARCHIVE.md after export: exact profile match, immutable package, one dispatch gate, full/raw verification, and no resend after corrections. Report only actual changes, failures, or needed user action; quiet no-op notifications do not disable separately authorized archival. Do not delete, archive, submit chat messages, change settings, collect bodies/credentials, expand the scope, or create another automation. Stop when this bounded run is finalized or its unresolved state is recorded.

Scheduling a prompt cannot make a locked, signed-out, unavailable, or ambiguous browser usable. Keep the limitation visible; do not automatically log in or manipulate another account to satisfy the schedule.
